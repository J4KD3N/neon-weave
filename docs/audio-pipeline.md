# Audio pipeline

How a recorded sound or a composed track gets into the game, and what the
game guarantees about it. Today every entry plays a synthesised placeholder
(`SynthWave`); a real file replaces it without a code change.
`docs/audio-status.md` (generated by `tools/audio_status.gd`) lists every
entry, what plays for it, and where the game fires it.

## Files

```
content/audio/<id>.json   sidecar (the contract: kind, volume, loop, and the synth fallback)
content/audio/<id>.wav    the recording, beside the sidecar (.ogg and .mp3 also read)
```

Mods ship sounds the same way under their own `content/audio/`. The base
game's folder is imported by Godot; a mod's is read straight from disk by
extension, so both paths work.

## Sidecar

```json
{
  "name": "Hit",
  "kind": "sfx",
  "file": "sfx_hit.wav",
  "volume_db": -6,
  "synth": { "wave": "noise", "freq": 400, "duration": 0.09, "sweep": -0.8, "decay": true, "volume": 0.5 }
}
```

- **kind**: `sfx` plays on the SFX bus through a pool of players; `music` plays on the Music bus and crossfades (`rules/audio.crossfade_seconds`).
- **file**: the recording beside the sidecar. Add the key when the file lands; the validator refuses a `file` that is not there or is not `.wav`, `.ogg` or `.mp3`.
- **loop**: music loops by default (`loop: true`); set `false` for a stinger. WAV loops forward over the whole file; give OGG music a clean loop point at the file's end.
- **volume_db**: the entry's level on its bus; the settings' Master, Music and Sound sliders sit on top.
- **synth**: the placeholder, kept so a missing file still makes a sound; delete it when the file is final if you want a missing file to fail loudly (the validator already reports it).

Music masters at about -14 dB LUFS, sound effects peak-normalised with the `volume_db` field doing the mix; both mono or stereo, 44.1 or 48 kHz.

## Where sounds are fired

- **Events** in `content/rules/audio.json`: `ui.*` (confirm, cancel, move, toast), `combat.*` (hit, miss, death, turn, summon, stealth, vent), `explore.*` (footstep, pickup, door, extract, level_up). The code fires the event name; the table names the entry.
- **Abilities** carry their own `sound` (an audio id); it plays before the hit or miss.
- **Tiles** carry a footstep `sound`; walking onto the cell plays it.
- **Music** is a state machine: `title`, `bastion`, `combat`, `explore` per biome. A state maps to a track id or to a table read in order: a variant (`combat.boss` when a boss is in the fight), `act<n>` (the story's act: 1 until first contact, 2 until the catastrophe, 3 after), the biome, then `default`. Add a variant by adding a key; the world already passes the act and the boss.

The full list with what is fired from where is `docs/audio-status.md`.

## Auditioning

```bash
godot --path . -- --play=sfx_hit
```

plays an entry as the game starts and prints whether the file or the synth
played. The settings screen's Music and Sound rows are the buses.

## The gate

```bash
godot --headless --path . -s tools/audio_status.gd -- --strict
```

exits 1 while any entry the game fires still plays the synth. CI runs the
tool without `--strict` and uploads the report; 1.0 runs it with.
